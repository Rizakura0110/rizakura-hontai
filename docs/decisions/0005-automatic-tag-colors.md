# ADR-0005: タグ色を重複しない色相から自動割当する

- Status: Accepted
- Date: 2026-08-28

## Context

記事には複数のタグを付け、各タグをチップとして表示する。利用者が色を選ぶ操作は不要だが、タグ同士を見分けやすくするため、基本的にタグごとの色は重複させない。

タグ名から都度色を計算すると、名前変更で色が変わる。単純な連番割当では、追加初期に近い色が並びやすい。表示順や記事との関連付けから色を決めると、同じタグの色が画面ごとに変わり得る。

## Decision

- タグごとに0〜359の整数`colorHue`をDBへ保存し、一意制約を設ける。
- タグ数は100件までとする。360色相より少ないため、同一色相を割り当てないことをDBでも保証できる。
- 最初のタグは青系の220度とする。2件目以降は、使用中の全色相との円環距離の最小値が最大になる色相を選ぶ。同点は小さい色相を優先し、結果を決定的にする。
- 同時作成で色相が競合した場合は、最新の使用色を読み直して最大3回再計算する。
- タグ名変更では`colorHue`を維持する。タグ削除後、その色相は将来のタグへ再利用できる。
- UIは`colorHue`を背景色へ変換し、文字色と彩度・明度は読みやすさを満たす固定規則で決める。利用者向けの色指定UIは設けない。

## Consequences

- 同じタグは、記事カード、絞り込み、設定画面で常に同じ色になる。
- 100タグまでは色相が完全には重複せず、追加時点で既存色からできるだけ離れた色が選ばれる。
- タグ数が増えるほど知覚上似た色は避けられない。色だけに意味を持たせず、必ずタグ名を併記する。
- 色相の一意制約と上限は将来変更できるが、変更時にはmigrationと表示コントラストの再検証が必要になる。
