# ADR-0007: URL保存時にタグ割り当てを同時確定する

- Status: Accepted
- Date: 2026-08-28

## Context

記事を保存してから別のdialogを開いてタグを付ける操作では、登録時点で分類が決まっていても二段階の操作が必要になる。新しい記事だけでなく、正規化後に同じURLと判定された登録済み記事へも、保存フォームで選んだタグを反映したい。

記事だけが作成されてタグ関連の保存に失敗する状態や、登録済み記事の既存タグを意図せず置き換える状態は避ける必要がある。

## Decision

- 記事作成requestへ重複のない`tagIds`を最大10件まで指定できるようにし、responseは保存後に記事へ付いているタグを返す。
- 新規記事、original URL alias、タグ関連はD1の同一batchで書き込み、いずれかが失敗した場合は記事だけを残さない。
- 正規化URLが登録済みの場合は新しい記事を作らず、既存のタグを維持したままrequestのタグを和集合として追加する。
- 和集合が1記事10タグを超える場合は、既存関連を変更せずvalidation errorを返す。存在しないタグIDもvalidation errorとする。
- 保存フォームでは既存タグを複数選択でき、その場でタグを作成して選択できる。タグ定義の作成は既存のタグAPIを使うため、作成後に記事保存を取り消した場合もタグ定義自体はcatalogへ残る。

## Consequences

- URL入力から保存までの1回の操作で記事カードへタグが表示される。
- 同じURLを再入力する操作を、記事を重複させずタグを追加する手段として利用できる。
- API responseのタグを利用して一覧状態を即時更新でき、保存直後の追加取得が不要になる。
- 新規タグを作った後に記事保存が失敗した場合、未使用タグが残る可能性がある。これは設定画面で削除でき、記事と関連を部分保存するより安全な挙動として受け入れる。
